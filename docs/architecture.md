# Архитектура текущего TTS-прототипа

Цель текущей ветки — качественный русский TTS на Jetson Orin Nano 8 GB без
PyTorch в процессе синтеза. Это исследовательский runtime, а не готовый сервис.

```text
русский текст
    │
    ├─ ru-normalizr: числа, даты, единицы и сокращения
    ├─ RUAccent ONNX: ударения и омографы
    └─ espeak-ng: фонемы
             │
             ▼
     phone encoder (TensorRT BF16)
             │
             ▼
     temp_former (TensorRT BF16 + CUDA Graph)
             │
             ▼
     dep_former (TensorRT BF16 + CUDA Graph)
             │
             ▼
     Mimi decoder (TensorRT BF16)
             │
             ▼
        PCM 24 kHz mono
```

`src/voxtream2_ru_jetson/` содержит только рабочий PyTorch-less путь. Модельные веса,
голос, fixed-prompt cache и TensorRT plans готовятся заранее. Для этого служат
`tools/` и диагностические программы из `experiments/tts/`.

## Что уже проверено

- Полный runtime завершает генерацию при `torch_imported=false`.
- Phone encoder, `temp_former`, `dep_former` и Mimi работают через TensorRT.
- CUDA Graph не изменил принятую траекторию и WAV в проведённой побитовой
  проверке.
- Фраза с датой, временем и процентами дала 0 неизвестных фонем. На Jetson она
  сгенерировала 10.96 секунды аудио за 10.15 секунды: RTF 0.926, TTFA ядра
  0.271 секунды, peak RSS 2.30 GiB.
- `SynthesisRuntime` держит frontend, engines и CUDA Graph в памяти. Два
  последовательных запроса с одинаковым текстом и seed дали побитово
  одинаковый WAV; второй запрос отдал первый PCM-чанк через 0.231 секунды.
- Публичный Python API выдаёт mono PCM `s16le` чанками по 80 мс. WAV CLI
  записывает тот же поток и не содержит отдельного генератора.
- Один dynamic `temp_former` plan содержит профили q=1 для обычного шага и
  q=420 для sink-attention replay. Второй набор весов не загружается.

## Где проходит граница результата

- Голос и prompt cache пока фиксированы заранее.
- Cold start всего resident runtime занимает около 14.5 секунды, но выполняется
  один раз. Цена переиспользования — рост peak RSS примерно с 2.30 до 3.50 GiB.
- Нормализация русского текста не закрыта по качеству: известны ошибки падежей,
  версий программ, телефонов и некоторых единиц.
- Sink-attention rebuild после позиции 624 повторяет политику upstream:
  сохраняет prompt и последние 312 temporal-входов, сбрасывает KV-cache и
  переигрывает их с новыми локальными позициями. В едином TensorRT plan
  q=420-профиль сократил replay 420 позиций с 7.317 до 0.112 секунды, а RTF
  длинной реплики — с 1.060 до 0.852. Plan весит 392.10 MB: примерно на 0.9 MB
  больше прежнего q=1 plan и не требует отдельного 336.71 MB replay plan.
  Peak RSS вырос только на 70 MiB относительно q=1-контроля. Первые 41.36
  секунды PCM совпали побитово; слепое A/B после compaction не выявило слышимой
  разницы.
- Resident-протокол пока последовательный. Клиент уже передаёт каждый PCM-чанк
  в ALSA до окончания реплики; отмена, несколько клиентов и проверка с
  физической USB-колонкой остаются следующими шагами.
